**Step 1: Fix Cargo.toml TLS backend**

Change the reqwest dependency from:
```toml
reqwest = { version = "0.13", features = ["json"], default-features = false }
```
to:
```toml
reqwest = { version = "0.13", features = ["json", "rustls-tls"], default-features = false }
```

This adds the rustls TLS backend so reqwest can make HTTPS requests to api.openai.com. Without this, all API calls fail at runtime with a connection error. Use `rustls-tls` (not just `rustls`) as this is the correct reqwest 0.13 feature name that enables the full rustls TLS stack with certificate verification.

**Step 2: Create src/openai/types.rs with all API serde types**

Create the `src/openai/` directory and `types.rs` file. All types are `pub(crate)` -- they are internal to the library, not part of the public API.

**Request types (Serialize only):**

- `ChatCompletionRequest`: model (String), messages (Vec of ChatMessage), temperature (Option of f64), max_tokens (Option of u32), tools (Option of Vec of ChatTool). All Option fields MUST have `#[serde(skip_serializing_if = "Option::is_none")]` so they serialize as absent, not null. OpenAI expects absent fields, not `"temperature": null`.

- `ChatMessage`: An enum with internally tagged serialization `#[serde(tag = "role")]`. Four variants:
  - `System` (renamed to "system"): content (String)
  - `User` (renamed to "user"): content (String)
  - `Assistant` (renamed to "assistant"): content (Option of String, skip_serializing_if), tool_calls (Option of Vec of ToolCallWire, skip_serializing_if)
  - `Tool` (renamed to "tool"): content (String), tool_call_id (String)

- `ChatTool`: tool_type (String, renamed to "type" via serde rename -- always "function"), function (ChatFunction)

- `ChatFunction`: name (String), description (String), parameters (serde_json::Value)

**Response types (Deserialize only):**

- `ChatCompletionResponse`: id (String), choices (Vec of Choice), usage (Option of Usage)

- `Choice`: index (u32), message (ResponseMessage), finish_reason (Option of String)

- `ResponseMessage`: role (String), content (Option of String -- MUST be Option because OpenAI returns `"content": null` when tool_calls are present), tool_calls (Option of Vec of ToolCallWire)

- `Usage`: prompt_tokens (u32), completion_tokens (u32), total_tokens (u32)

**Shared types (both Serialize and Deserialize):**

- `ToolCallWire`: id (String), call_type (String, renamed to "type" via serde -- always "function"), function (FunctionCallWire). This is the nested tool call structure OpenAI uses.

- `FunctionCallWire`: name (String), arguments (String -- raw JSON string, not parsed)

**Error response types (Deserialize only):**

- `ApiErrorResponse`: error (ApiErrorBody)

- `ApiErrorBody`: message (String), error_type (String, renamed to "type"), param (Option of String), code (Option of String)

Add doc comments explaining the purpose of this module (OpenAI API wire format types, separate from internal library types per 01-01 decision). Reference that Message does NOT derive Serialize/Deserialize and this module bridges the gap.
