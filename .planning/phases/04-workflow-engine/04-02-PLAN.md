use std::collections::HashMap;
use serde_json::Value;
use crate::error::{Error, Result};
use crate::message::Message;

Signature: `pub async fn execute(&self) -> Result<HashMap<String, Value>>`

Implementation:
1. Create `let mut outputs: HashMap<String, Value> = HashMap::new();`
2. Iterate over `self.execution_order()`:
   a. For each step name, gather inputs by calling `self.dependencies(step_name)` and looking up each dependency's output in `outputs`. Build a `StepInput` HashMap with `dep_name -> outputs[dep_name].clone()`.
   b. Get the step via `self.step(step_name).unwrap()` (safe because execution_order only contains valid names from a validated Workflow).
   c. Match on the step variant:
      - `Step::Transform { transform }` -- call `transform(&inputs)?` to get the output Value.
      - `Step::Llm { model, prompt_builder, tools, options }` -- call `execute_llm_step(model.as_ref(), prompt_builder.as_ref(), tools, options, &inputs).await?` to get the output Value.
   d. Insert the output into `outputs` with the step name as key.
3. Return `Ok(outputs)`.

**`execute_llm_step` private helper function:**

Signature:
```rust
async fn execute_llm_step(
    model: &dyn crate::model::Model,
    prompt_builder: &(dyn Fn(&StepInput) -> String + Send + Sync),
    tools: &Option<crate::tool::ToolRegistry>,
    options: &crate::types::ModelOptions,
    inputs: &StepInput,
) -> Result<Value>
```

Implementation:
1. Build the prompt: `let prompt = prompt_builder(inputs);`
2. Create messages: `let messages = vec![Message::user(prompt)];`
3. Call the model based on whether tools are configured:
   - If `Some(registry)`: call `model.chat_with_tools(&messages, &registry.definitions(), options).await?`
   - If `None`: call `model.chat(&messages, options).await?`
4. Handle the response:
   - `ModelResponse::Text(text)` -- return `Ok(Value::String(text))`
   - `ModelResponse::ToolCalls(calls)` -- dispatch tools:
     a. Get the registry via `tools.as_ref().ok_or_else(|| Error::InvalidWorkflow("model returned tool calls but no tools configured".into()))?`
     b. Call `registry.dispatch_all(&calls).await?` to get `Vec<Message>` results.
     c. Map results to Values: `results.iter().map(|m| Value::String(m.content.clone())).collect::<Vec<Value>>()`
     d. Return `Ok(Value::Array(result_values))`

2. Update `src/workflow/mod.rs` to add the executor module:
   - Add `pub mod executor;` to the module declarations.
   - No additional re-exports needed since execute is a method on Workflow (already re-exported).

3. Run `cargo check` to verify compilation.

**Mock Model for testing:**

Create a `MockModel` struct that implements `Model` via `#[async_trait]`. It takes a fixed response string at construction time and returns it as `ModelResponse::Text(response)` from both `chat()` and `chat_with_tools()`. This avoids any real HTTP calls.

```rust
struct MockModel {
    response: String,
}

impl MockModel {
    fn new(response: impl Into<String>) -> Self {
        Self { response: response.into() }
    }
}

#[async_trait::async_trait]
impl crate::model::Model for MockModel {
    async fn chat(&self, _messages: &[Message], _options: &ModelOptions) -> Result<ModelResponse> {
        Ok(ModelResponse::Text(self.response.clone()))
    }
    async fn chat_with_tools(&self, _messages: &[Message], _tools: &[ToolDefinition], _options: &ModelOptions) -> Result<ModelResponse> {
        Ok(ModelResponse::Text(self.response.clone()))
    }
}
```

**Test 1: `test_three_step_linear_workflow` (Success Criterion #5)**

This is THE critical integration test. Build: transform -> LLM call -> transform.

Steps:
- `"format_input"` (Transform): ignores inputs, returns `json!({"topic": "Rust"})`.
- `"generate"` (Llm): prompt_builder reads `inputs["format_input"]["topic"]` and builds a prompt. MockModel returns a fixed string like `"Rust is great"`.
- `"format_output"` (Transform): reads `inputs["generate"]` (which is `Value::String("Rust is great")`), wraps it in `json!({"result": text, "formatted": true})`.

Edges: `("format_input", "generate")`, `("generate", "format_output")`.

Assertions:
- `outputs.len() == 3` (all steps produced output)
- `outputs["format_input"] == json!({"topic": "Rust"})`
- `outputs["generate"] == json!("Rust is great")` (Value::String)
- `outputs["format_output"]["result"] == "Rust is great"`
- `outputs["format_output"]["formatted"] == true`

**Test 2: `test_transform_only_workflow`**

Two transform steps in sequence. Step A produces a number, step B doubles it.
- `"produce"` (Transform): returns `json!(42)`.
- `"double"` (Transform): reads `inputs["produce"]` as i64, returns `json!(value * 2)`.
- Edge: `("produce", "double")`.
- Assert `outputs["double"] == json!(84)`.

**Test 3: `test_independent_steps_all_execute`**

Three independent transform steps (no edges). All should execute and appear in outputs.
- `"a"`, `"b"`, `"c"` -- each returns a distinct value.
- No edges.
- Assert all three are in outputs.

**Test 4: `test_diamond_data_flow`**

Diamond DAG: A -> B, A -> C, B -> D, C -> D. Verify that D receives outputs from both B and C.
- `"source"` (Transform): returns `json!({"value": 10})`.
- `"left"` (Transform): reads source value, adds 1 -> `json!(11)`.
- `"right"` (Transform): reads source value, adds 2 -> `json!(12)`.
- `"sink"` (Transform): reads both left and right values, sums them -> `json!(23)`.
- Assert `outputs["sink"] == json!(23)`.
